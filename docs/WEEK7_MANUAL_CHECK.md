# Android 수동 검증·촬영 체크리스트

본인 `.env`가 있는 PC에서 Android 에뮬레이터 또는 실제 기기로 `flutter run -d <id>`를 실행한다. 실제 계정 생성 및 평점 저장은 본인이 만든 학습용 계정에서만 수행한다. 이 문서의 체크박스는 실제 촬영 후 체크한다.

## Guided A: 가입

- [ ] 닉네임 2~12자 / 이메일 형식 / 비밀번호 규칙 위반으로 로컬 오류를 확인한다.
- [ ] 닉네임 확인만 통과하면 가입하기는 비활성이다. 이메일도 확인하고 약관에 동의하면 활성화된다.
- [ ] 확인 후 닉네임 또는 이메일 한 글자를 변경하면 다시 비활성화된다.
- [ ] 가입하기를 한 번 누르면 버튼이 로딩되고 입력·뒤로가기가 잠긴다.
- [ ] 성공 Snackbar에 memberId가 표시되고 영화 목록으로 이동한다. 마이 탭 행에서도 같은 ID를 확인한다.
- [ ] 비밀번호는 화면 캡처·로그·문서에 남기지 않는다. 토큰도 촬영하지 않는다.

최종 409는 두 중복 확인이 통과한 뒤 POST 직전에 다른 가입이 발생한 경합이다. 단순히 이미 등록된 값을 다시 확인하면 GET available=false에서 막히므로 그것만으로 최종 POST 409를 촬영했다고 쓰지 않는다. `test/week7_test.dart`가 이 경합 결과를 가상 응답으로 검증한다. 실서버 경합은 본인 계정과 두 실행 인스턴스에서만 재현한다.

## Guided B: 등록 → 조회

- [ ] 영화 탭의 TMDB 영화 카드를 선택한다. 실제 movie.id를 기록한다.
- [ ] 상세에서 평점 남기기를 누른다. 별점 미선택 시 코멘트를 써도 확인은 비활성이다.
- [ ] 별 1~5점을 선택하고 500자 이내 코멘트를 쓴다.
- [ ] 확인 중에는 버튼이 로딩되고 취소·뒤로가기·바깥 탭으로 닫히지 않는다.
- [ ] 완료 후 상세 화면의 성공 Snackbar를 촬영한다.
- [ ] 마이 → 내가 등록한 평점에서 같은 영화·별점·코멘트가 보인다.
- [ ] 목록은 왼쪽 뒤로가기·중앙 제목이 있고 하단 탭이 없다.
- [ ] 같은 영화 재등록은 409 메시지가 나오며 Dialog의 입력은 유지된다. 취소해서 닫는다.

## Required: 수정 → 조회

- [ ] 카드의 수정 버튼으로 Dialog를 열면 기존 점수·후기가 채워져 있다.
- [ ] 점수만 바꿔 저장하면 후기가 유지된다.
- [ ] 후기를 모두 지워 저장하면 목록에서 후기가 사라진다.
- [ ] 저장 뒤 GET으로 목록이 갱신된다.

## Required: 삭제 취소 / 성공 / 빈 목록

- [ ] 삭제 버튼을 눌렀을 때 확인 Dialog가 먼저 뜬다.
- [ ] 취소하면 기존 카드가 그대로다. DELETE 요청은 전송되지 않는다.
- [ ] 다시 삭제하고 확인하면 삭제 중 Dialog와 로딩이 유지된다.
- [ ] 삭제 후 GET으로 카드가 사라지고 마지막 평점 삭제 시 “등록된 평점이 없습니다.”가 보인다.

## 실패 복구 촬영

- [ ] 작성 중 비행기 모드/네트워크 연결 해제 후 저장 → 오류와 기존 입력이 유지된다. 네트워크 복구 후 같은 Dialog에서 다시 시도한다.
- [ ] 저장 성공 후 GET만 실패 → “저장은 완료됐지만…” 안내와 “목록 새로고침 (GET)” 버튼을 확인한다.
- [ ] 버튼을 눌러 GET만 재시도한다. POST/PATCH/DELETE가 반복되지 않는지 확인한다.

마지막 두 번째 시나리오는 요청별 오류 주입이 필요하다. Android Studio Network Inspector와 테스트 프록시/학습용 서버에서 **GET 평점 조회만** 실패시킨다. 단순히 네트워크 전체를 차단하면 쓰기까지 실패해 다른 시나리오가 된다. 자동 테스트는 이 순서를 이미 검증한다. 403/404도 타인 데이터 수정 대신 가상 API 테스트로 검증한다.
